01

动机

我们的目标是建立能够完成长程复杂任务，并且能够不断迭代优化的智能体机器人（agentic robot）。

1.1  为什么是智能体机器人

编程智能体能完成长程任务，靠的是“编写、运行、查看结果、修改”这个循环。我们认为，机器人也可以采用同样的范式。

问题

视觉-语言-动作模型（VLA）和世界-动作模型（WAM）目前已经能很好地完成单个短动作，但长程复杂任务对它们来说仍然很难。这类任务需要的不只是动作。比如，机器人要先观察一遍分拣顺序，再凭记忆复现出来；要先解出一道方程，再把答案摆放出来；要根据一句话的描述，拿起对应的物体；要会下井字棋；最后还要检查每个条件是否都已满足。

难点在于，端到端策略需要在同一次前向推理中同时完成思考和动作，并且每秒要执行很多次。一旦早期出现错误，后续所有动作都会受到影响，而策略在执行过程中没有停下来检查的机会。

思路

数字世界也遇到过同样的问题，并且已经找到了解决办法，那就是编程智能体。在编程智能体中，通用模型不追求一次写出正确答案，而是先写一段代码，运行后查看结果，再根据结果进行修改。借助工具，不断重复这个循环，它就能完成长程任务。我们希望把这种技术范式适配到机器人上。

这一思路过去难以用在机器人上，是因为缺少一个能够理解物理场景的通用模型。GPT-6 Astra 改变了这一点：它在具身推理和操作上的早期评测表明，通用模型已经可以驱动机器人。整个方向的进展也因此大大加快。

架构

据此，我们把系统设计为三层。

最上层是 System 2，即基础模型，负责把长程任务拆分为子任务。任何能力足够的模型都可以担任这一层。

中间层是 System 1，即技能和工具，负责完成每一个子任务。这一层是开放的：目标检测、分割、SLAM 与路径规划、视觉伺服等传统技术可以直接接入；VLA 或 WAM 也可以封装成技能，像其他技能一样被调用。

最底层是 System 0，即运动规划与控制，负责把技能给出的目标转换为关节运动。

三层合在一起，就是我们所说的智能体机器人（agentic robot）。它并不是要取代 VLA，而是把 VLA 擅长的短动作作为众多技能中的一项，把长程部分交给 System 2 来处理。

这个预览版

HyperBrain-RSI-Preview 是这一架构的第一个版本：基础模型采用 Claude Opus 5.5；技能层包括图像分割、基于像素的测量，以及为每个任务编写的几个 Python 工具；运动规划由 cuRobo 完成。

虽然只是第一个版本，它已经体现出三方面的优势。

首先，新增任务的成本很低。一个新任务只需要几段笔记和几个 Python 函数，不需要新的示范数据，也不需要训练。全部 54 个任务配置使用的是同一个模型和同一套运动原语；基准提供的示范只在编写笔记时作为参考，没有用于训练任何网络。

其次，失败可以追溯。一个回合（episode）失败后，会留下它编写的程序、推理过程和测量数据，从日志中可以直接定位到出错的那一行。相比之下，策略模型失败后只会留下一段视频。

最后，基础模型可以随时更换。它只是配置文件中的一项设置，当更强的模型出现时，既不需要重新采集数据，也不需要重新训练。

留下的问题

但这也带来了一个新问题：每个任务所需的笔记和工具，应该由谁来编写？这正是第二个想法要回答的。

1.2  为什么要自进化

真正的瓶颈不是智能，而是对这具身体的经验。经验只能从实际操作中获得，因此需要有一个环节，把运行日志转化为知识。

通用模型知道塔是什么，也能规划如何搭建，但它并不了解这台机器人的具体情况：物体被这个夹爪夹住后会如何下垂，这个仿真器要求按钮按到多深，这两条机械臂又有多大概率会拒绝执行一次移动。右侧几行摘自执行智能体当前使用的提示词，记录的正是这类经验。

这些经验无法从第一性原理推导出来。提示词中的每一行，都对应着某个回合实际遇到的问题。

摘自提示词

A held object hangs below the fingers: gripped by a rim it tilts (about 40 degrees in our runs) and its lowest point sits about 0.7 of its width below the TCP.

Press, strike, push and insert past first contact: aim about 1 cm beyond the measured contact surface […] Stopping at the surface does not register.

About one move or move_both in ten fails without moving (unreachable, no_line, collision).

这些经验存放在 harness 中。模型的权重位于 API 之后，我们无法改动；除权重之外，智能体的其余部分都属于 harness，全部由纯文本和 Python 代码构成。harness 包括三个部分：一是运行时，包括调用模型的循环、运行程序的沙箱、与仿真器的接口和日志；二是所有任务共享的部分，包括手册、技能和运动原语；三是每个任务各自的笔记和工具。那么，这些笔记和工具为什么应该交给模型自己来改写？原因有四点。

  1. 身体的特性只能通过尝试发现。这些特性需要告诉模型，但在此之前，必须先在实际运行中遇到并发现它们。
  2. 能修改的只有文本和代码，而这恰恰是语言模型最擅长的。日志是可读的，harness 是可写的，因此阅读失败记录、编写下一个版本的工作，也可以交给语言模型来完成。
  3. 手工编写难以规模化。基准共有 54 个配置，每个配置都有各自的失败方式。
  4. 每一次修改都可以验证。新版本会与当前版本在相同的十个场景上比较，只有得分更高才会被保留；最终成绩则在一个任何一轮都没有运行过的种子上测量。

基于以上考虑，我们设置了两个智能体：负责执行任务的称为执行智能体，负责改写其 harness 的称为优化智能体。优化智能体只改写 harness 的第三部分，即每个任务的笔记和工具；前两部分由人工编写。

两个智能体配合，构成了一个循环。这个循环写成公式只有三行，写成伪代码也只有十几行：

An=Agent(F, Hn)
Δn=Improve(Hn, Ln)
Hn+1=Hn⊕Δn若V(Hn⊕Δn)>V(Hn)

运行，读取日志，改写 harness，只有得分更高才保留。

F
基础模型，始终不变：Claude Opus 5.5（high）
Hn
第 n 轮之后的 harness；会变的只有任务的笔记和工具
An
执行智能体，即 F 配上 Hn
Ln
它跑出的回合日志：程序、推理、测量值、得分
Δn
对笔记和工具提出的一次修改
V
十个验证场景上官方得分的平均值
H[0] = initial_harness(task)起点for n in range(rounds):    A = Agent(F, H[n])固定的模型 + harness    L = A.run(layouts)运行回合 → 日志    Δ = improve(H[n], L)优化智能体提出修改    assert guard(Δ)静态检查    if V(H[n] ⊕ Δ) > V(H[n]):10 个验证场景        H[n+1] = H[n] ⊕ Δ保留    else:        H[n+1] = H[n]丢弃score = test(Agent(F, H[-1]))留出的种子

Improve = 读取 → 修改 → 检查 → 验证 → 保留或舍弃。

由于 F 始终不变，得分的任何变化都只能来自 H。以 build_tower 任务为例：执行智能体需要先立起四根柱子，再在上面架设木板，最后放上屋顶。

第 3 轮的修改让执行智能体变得更快：两个夹爪同时开合、全速运动，并在两种等效的手腕旋转方式中选择代价更小的一种。然而，这一版虽然完成了一个第 2 轮没有完成的场景，却在另外两个场景上失败了，因此按规则被舍弃。分析这一轮的失败记录后，我们找到了柱子倒塌的原因：两个张开的夹爪在手腕仍在旋转时从柱子上方落下，把柱子扫倒了。第 4 轮在保留速度的同时，增加了放置木板和屋顶的工具，最终完成了全部十个验证场景。

这样的提升并非个例。在整个基准上，初始版本的 harness 在训练场景（每个配置十个）上得分为 38.9，最终版本在测试种子上得分为 78.87，而基础模型始终没有更换。

由谁来改进？改进由优化智能体完成，而不是人。它同样是 Claude：每一批运行结束后，它读取日志，找出导致失败的原因，然后修改相应任务的笔记和工具。

1.3  为什么选 RoboDojo

我们选择在 RoboDojo 上测试这一版本，主要有三个原因。第一，它的 42 个仿真任务涵盖精度、长程、记忆、开放指令和泛化，正是本节开头提到的长程复杂任务。第二，训练得到的策略和智能体使用同一个脚本评分，并在同一个公开排行榜上排名。第三，它是仿真环境，下一个版本可以在完全相同的场景上重新运行，开发和报告成绩也可以使用不同的种子。

02

方法

执行智能体完成一次任务的过程称为一个回合，形式上是模型与一个 Python 会话之间的对话：模型编写程序，会话在机器人上运行程序，然后返回程序打印的内容以及模型请求的相机图像。模型编写下一段程序时，所能依据的只有这些信息。

2.1  输出程序，而不是动作

模型从不直接输出动作。每次调用时，它都会编写一段程序：程序把多个动作串联起来，逐一检查每个动作的结果，一旦失败就立即停止。

这样设计，首先是因为时间尺度不匹配：一次模型调用需要数秒，而一个控制步只有 40 ms，不可能每一步都询问模型。在一个 stack_blocks 回合中，机器人执行了 515 步，模型只被调用了 6 次。

编写程序还有三点好处。第一，每个运动原语都会返回是否成功以及错误码，因此下一步决策依据的是实际发生的情况，而不是原先的计划。第二，观察和测量不消耗环境步数，只有运动才会消耗，因此程序可以先完成所有测量，再连续执行动作。第三，当一个回合失败时，总能定位到出错的那一行。

2.2  测量，而不是假设

程序中用到的每个位置，都是在回合中通过三台 RGB 相机实时测量得到的，既不使用深度图像，也不使用物体模型。

仅凭 RGB 图像定位，需要满足一定的条件。单个视角只能给出一条射线，只有当目标点位于桌面这样的已知平面上时，才能确定其位置。使用两个视角时，要求每条射线到该点的距离都在 3 mm 以内，并且射线之间的夹角不小于 10°；夹角小于 10° 时，一个像素的匹配误差就会导致超过一厘米的位置偏差。

条件不满足时，测量会失败，但系统并不只是返回一个错误，而是会给出需要观察的位置。模型随后把腕部相机移到那里，再次测量。

2.3  改进可读的部分

以上两部分介绍的是执行智能体如何工作，这一部分介绍它如何进化。模型权重始终不变；每两轮之间，优化智能体只改写任务的笔记和工具，并且只有得分更高的修改才会被保留。

笔记和工具各有分工。笔记记录的是通用模型事先无法知道的内容，每一行都来自某个回合遇到的问题；当一条经验是一套完整的操作流程时，就把它写成工具，也就是基于同一套运动原语的普通 Python 代码。

修改也有明确的限制。每次修改只能涉及所属的任务，工具中也不能根据任务名称设置分支，因为全部 54 个配置都由同一个执行智能体运行。此外，各轮改进只在种子 0 和 1 上进行，我们报告的成绩来自任何一轮都没有使用过的种子 2。

03

结果

自测结果。我们使用基准自带的脚本，在种子 2 上自行运行了全部 54 个配置，共 2,100 个回合。运行开始前，笔记和工具已经全部冻结。

模型类型平均平均（不含开放指令）泛化精度长程记忆开放指令
HyperBrain-RSI-Preview智能体78.87/ 73.50%79.11/ 73.56%51.18/ 45.00%91.08/ 88.75%78.01/ 64.50%96.17/ 96.00%77.90/ 73.25%

得分 / 成功率，各列与 RoboDojo 仿真排行榜一致。泛化是标准和随机两个变体的平均值，平均是五个维度的平均值。泛化任务每个配置运行 25 个场景，其余任务运行 50 个。

从各维度来看，执行智能体在以决策为主的任务（记忆，96.17）和需要精确放置刚性物体的任务（精度，91.08）上表现最好。54 个配置中，有 24 个得分达到 90 或以上。

相比之下，它在两个泛化组上表现最弱，得分分别为 52.37 和 50.00。涉及布料、双臂交接以及接触后容易滑动的物体的任务，大多集中在这两组。

除了得分，运行成本同样值得关注。2,100 个回合的模型调用费用共计 1,219.51 美元，平均每个回合约 0.58 美元。根据排行榜上其他智能体公开的信息，我们估算它们每个回合的花费约为 1 到 2.5 美元。

成本较低主要有三个原因。第一，一次调用编写的程序可以运行很多步，因此一个回合只需要少量调用（见 2.1 节）。第二，位置在本地测量，并以数值形式返回；模型只能看到最近三次观察的图像，以及它选择保留的最多三张图像，因此图像不会在对话中不断累积。第三，每次调用时，提示词和之前的对话内容都从缓存中读取。

此外，生成这些笔记和工具的各轮改进，模型调用费用约为 2,300 美元。
